---

## 1. 目标与非目标

### 1.1 目标

- 在后端 Agent 全链路实现按用户维度的记忆读写，支持跨会话连续性。
- 使用 JWT 中的后端用户 ID 作为唯一身份主键，确保安全和稳定。
- 长期记忆仅存于阿里云记忆库，避免多事实源导致一致性问题。
- 采用异步队列 + 重试机制，保证主业务低延迟与记忆最终一致写入。
- 同时启用记忆片段与用户画像；对敏感画像字段执行“只存不召回”。

### 1.2 非目标

- 不在本阶段建设本地长期记忆数据库（本地仅做异步缓冲与重试）。
- 不在本阶段引入新的消息中间件（Kafka/RabbitMQ）；优先复用现有 Redis。
- 不在本阶段实现多记忆库路由策略（固定单库）。

---

## 2. 关键决策（已确认）

1. **覆盖范围**：全量 Agent 相关链路。
2. **用户标识**：统一使用 JWT 解析得到的后端 `userId`。
3. **记忆类型**：记忆片段 + 用户画像。
4. **敏感策略**：敏感字段只存不召回（不注入 Prompt）。
5. **写入可靠性**：异步队列 + 重试 + 死信队列（DLQ）。
6. **持久化边界**：长期记忆仅存阿里云记忆库 `5eb944ee565c400d8fb71e6ab119dfe3`。

---

## 3. 总体架构

### 3.1 架构原则

- **单一事实源**：长期记忆以阿里云记忆库为准。
- **读写解耦**：业务请求线程只负责召回和入队，不阻塞在写云。
- **安全优先**：敏感画像不进入 Prompt，上下文注入必须经过字段白名单。
- **统一封装**：通过 `MemoryFacade` 统一记忆能力，避免 Controller 层重复实现。

### 3.2 逻辑流程

1. 请求进入后端，认证层解析 JWT，得到 `userId`。
2. `MemoryFacade` 先调用阿里云 `SearchMemory` 获取候选记忆。
3. 执行召回白名单过滤，仅注入允许字段到 Prompt。
4. Agent 生成回答，业务接口返回。
5. 对话轮次封装为 `MemoryEvent` 投递 Redis Stream。
6. 消费者异步调用阿里云 `AddMemory` 写入记忆片段和画像。
7. 失败按重试策略回退；超限进入 DLQ，触发告警。

## 4. 数据模型与参数

### 4.1 身份键规范

- `memory_user_id = "sparklink:user:" + <jwt.userId>`
- 仅后端通过 JWT 解析生成，不接受客户端直接传入。

### 4.2 队列事件模型（MemoryEvent）

- `eventId`：UUID，事件唯一标识。
- `traceId`：请求链路追踪 ID。
- `userId`：后端用户 ID（Long）。
- `memoryUserId`：规范化记忆用户 ID（String）。
- `messages`：本轮会话消息（user + assistant）。
- `occurredAt`：事件发生时间戳（毫秒）。
- `knowledgebaseId`：`5eb944ee565c400d8fb71e6ab119dfe3`。

### 4.3 阿里云调用参数约定

- **写入（AddMemory）**
  - `user_id = memory_user_id`
  - `messages = [{role, content}, ...]`
  - `knowledgebase_ids = ["5eb944ee565c400d8fb71e6ab119dfe3"]`
- **检索（SearchMemory）**
  - `user_id = memory_user_id`
  - `query = 当前用户问题`
  - `knowledgebase_ids = ["5eb944ee565c400d8fb71e6ab119dfe3"]`
  - `max_results = 8`
  - `similarity_threshold = 0.6`

## 5. 用户画像字段策略

### 5.1 已配置画像字段

- 年龄段、居住地、社会关系（朋友圈）、宠物、人生理想/目标、民族、饮食习惯、爱好、性别、年龄、家庭成员、内容偏好。

### 5.2 召回与注入策略

- **只存不召回（敏感）**：民族、性别、年龄、家庭成员。
- **可召回**：年龄段、居住地、社会关系（朋友圈）、宠物、人生理想/目标、饮食习惯、爱好、内容偏好。

### 5.3 注入防护

- Prompt 注入前执行白名单过滤。
- 当过滤组件异常时，按保守策略不注入任何画像字段。

---

## 6. 幂等、重试与死信

### 6.1 幂等键

- `idempotencyKey = sha256(userId + eventId + userMsgHash + assistantMsgHash)`
- 消费前执行 Redis `SETNX(memory:idem:{idempotencyKey})`，TTL 7 天。
- 命中幂等键则跳过写入，避免重复记忆。

### 6.2 重试策略

- 最大重试次数：6 次。
- 退避序列：5s、30s、2m、10m、30m、2h。
- 可重试：网络超时、5xx、429。
- 不可重试：参数错误等 4xx（直接 DLQ）。

### 6.3 死信策略

- 超过重试上限进入 DLQ。
- DLQ 保留 7 天，支持人工与脚本重放。
- DLQ 增量触发告警。

---

## 7. 错误处理与降级

- `SearchMemory` 失败：降级为空记忆，不阻断主业务回答。
- `AddMemory` 失败：异步重试，不影响本次 API 响应。
- 阿里云短暂不可用：系统继续服务，待恢复后通过重试补齐记忆。
- 过滤器故障：停止注入画像，保留基础业务回答。

## 8. 观测与告警

### 8.1 核心指标

- `search_success_rate`
- `add_success_rate`
- `queue_lag`
- `retry_avg_count`
- `dlq_count`
- `memory_write_latency_p95`
- `memory_recall_hit_rate`
- `sensitive_field_injection_block_count`

### 8.2 告警阈值（初始）

- `add_success_rate < 99%`（5 分钟窗口）
- `dlq_count > 0` 持续 5 分钟
- `queue_lag` 持续增长 10 分钟
- 敏感字段注入拦截异常突增

---

## 9. 验收标准

- 同一 `memory_user_id` 跨会话稳定召回。
- 不同 `memory_user_id` 记忆严格隔离，无串号。
- 敏感字段不进入 Prompt（自动化校验 + 抽检通过）。
- 阿里云故障期间主业务可用；恢复后最终写入达成。
- 重复消费不产生重复记忆。

## 10. 测试计划

### 10.1 单元测试

- `memory_user_id` 生成规则。
- 白名单过滤逻辑。
- 幂等键计算与去重。

### 10.2 集成测试

- 记忆写入 -> 检索闭环。
- 多用户并发隔离。
- 敏感字段“只存不召回”验证。

### 10.3 异常与容灾

- 429 / 5xx / 超时重试路径。
- DLQ 入列与重放。
- 过滤器异常保守降级。

### 10.4 性能测试

- 高并发下入队成功率与队列堆积恢复速度。
- `SearchMemory` 对整体接口时延影响评估（P95/P99）。

### 11.2 后续演进

## 12. 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 云端限流导致写入延迟 | 退避重试 + DLQ + 队列监控 |
| 检索噪声影响回答质量 | 白名单过滤 + 阈值调优 + 重排 |
| 敏感字段误注入 | 严格白名单 + 审计日志 + 自动化测试 |
| 重复消费导致重复写入 | 幂等键 + SETNX 去重 |
