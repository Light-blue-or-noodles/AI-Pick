# MemOS Cloud 插件与 OpenClaw 记忆系统的协作实践

## 9 MemOS Cloud 插件使用实践

### 9.1 为什么需要 MemOS Cloud 插件

在多 Agent 协作开发过程中，我们遇到了一个核心问题：**Agent 之间的记忆无法共享**。

**问题场景**：
- backend-agent 完成了数据库设计，但 frontend-agent 不知道字段变更
- review-agent 发现了代码规范问题，但其他 Agent 重复犯同样的错误
- pm-agent 更新了产品需求，但开发 Agent 还在按旧需求开发

**传统解决方案的局限**：
- OpenClaw 自带的 MEMORY.md 是文件级记忆，需要 Agent 主动读取
- 跨会话的记忆检索效率低，容易遗漏关键信息
- 没有语义搜索能力，无法基于相似场景自动回忆

**MemOS Cloud 插件的价值**：
- 提供云端记忆存储，支持多 Agent 共享
- 自动捕获关键决策、错误教训、最佳实践
- 语义搜索能力，基于场景自动回忆相关经验
- 生命周期钩子，在关键节点自动触发记忆操作

### 9.3 核心功能详解

#### 9.3.1 自动回忆（Auto-Recall）

**功能说明**：在 Agent 处理任务前，自动从 MemOS Cloud 检索相关历史记忆，注入到当前会话上下文。

**工作原理**：
```
用户发送任务请求
    ↓
MemOS 插件拦截请求
    ↓
提取任务关键词（如"搭子列表接口"）
    ↓
语义搜索相关记忆
    ↓
将记忆片段注入系统提示词
    ↓
Agent 基于增强上下文处理任务
```

**配置示例**：
```yaml
# memos-config.yaml
auto_recall:
  enabled: true
  trigger_keywords: ["接口", "API", "Controller", "Service"]
  max_memories: 5
  similarity_threshold: 0.75
  filters:
    agent: ["backend-agent"]
    type: ["LEARNING", "DECISION", "ERROR"]
```

**实际效果**：
- backend-agent 创建新接口时，自动回忆之前定下的 RESTful 规范
- 避免重复犯同样的代码规范错误
- 新任务能继承之前积累的最佳实践

#### 9.3.2 记忆捕获（Memory Capture）

**功能说明**：在关键节点自动捕获重要信息，存储到 MemOS Cloud。

**捕获时机**：

| 时机 | 捕获内容 | 存储类型 |
|------|----------|----------|
| 任务完成时 | 任务结果、关键决策 | DECISION |
| 发现错误时 | 错误原因、解决方案 | ERROR |
| 审查通过时 | 代码优点、改进建议 | LEARNING |
| 需求变更时 | 变更原因、影响范围 | DECISION |

**配置示例**：
```yaml
memory_capture:
  enabled: true
  triggers:
    - event: task_complete
      capture: ["task_description", "solution", "key_decisions"]
    - event: error_occurred
      capture: ["error_message", "root_cause", "fix_solution"]
    - event: review_passed
      capture: ["code_quality_score", "best_practices", "improvement_suggestions"]
```

**实际效果**：
- 自动记录每个任务的完成情况和关键决策
- 错误教训被捕获，其他 Agent 可以学习
- 形成可检索的知识库，避免重复踩坑

#### 9.3.3 语义搜索（Semantic Search）

**功能说明**：基于自然语言描述，搜索语义相似的历史记忆。

**使用场景**：
```
场景 1：Agent 遇到报错，搜索"MyBatis 绑定错误"
场景 2：设计新接口，搜索"RESTful 规范"
场景 3：review 代码，搜索"代码审查清单"
```

**搜索示例**：
```python
# Agent 内部调用
memories = memos.search(
    query="如何设计分页查询接口",
    filters={
        "agent": "backend-agent",
        "type": "LEARNING",
        "date_range": "last_30_days"
    },
    limit=5
)
```

**返回结果**：
```json
{
  "memories": [
    {
      "id": "mem_123",
      "content": "分页查询接口设计规范：使用 PageHelper，返回 PageInfo 对象...",
      "similarity": 0.92,
      "source": "backend-agent",
      "timestamp": "2026-03-15T10:30:00Z"
    },
    {
      "id": "mem_456",
      "content": "PartnerController 分页实现案例：pageNum/pageSize 参数校验...",
      "similarity": 0.88,
      "source": "review-agent",
      "timestamp": "2026-03-14T16:45:00Z"
    }
  ]
}
```

#### 9.3.4 生命周期钩子（Lifecycle Hooks）

**功能说明**：在 Agent 生命周期的关键节点自动执行记忆操作。

**钩子类型**：

| 钩子 | 触发时机 | 功能 |
|------|----------|------|
| on_session_start | 会话开始时 | 自动回忆相关记忆 |
| on_task_receive | 接收到任务时 | 搜索相似任务历史 |
| on_task_complete | 任务完成时 | 捕获任务结果 |
| on_error | 发生错误时 | 记录错误和解决方案 |
| on_session_end | 会话结束时 | 总结会话关键信息 |

**配置示例**：
```yaml
lifecycle_hooks:
  on_session_start:
    action: auto_recall
    params:
      query: "session_context"
      limit: 10
  
  on_task_receive:
    action: semantic_search
    params:
      query: "{{task_description}}"
      limit: 3
  
  on_task_complete:
    action: capture_memory
    params:
      type: "DECISION"
      content: "{{task_result_summary}}"
  
  on_error:
    action: capture_memory
    params:
      type: "ERROR"
      content: "{{error_details}}"
      tags: ["error", "{{agent_name}}"]
```

### 9.4 MemOS 与 OpenClaw 记忆系统的协作关系

#### 9.4.1 两者定位差异

| 维度 | OpenClaw 记忆系统 | MemOS Cloud 插件 |
|------|-------------------|------------------|
| **存储位置** | 本地文件（MEMORY.md） | 云端服务 |
| **数据格式** | Markdown 文本 | 结构化数据 + 向量 |
| **检索方式** | 关键词匹配 | 语义搜索 |
| **共享范围** | 单 Agent | 多 Agent 共享 |
| **生命周期** | 持久化存储 | 可设置过期策略 |
| **主要用途** | 当前任务状态、待办事项 | 历史经验、最佳实践 |

#### 9.4.2 协作模式

两者并非竞争关系，而是**互补协作**：

```
┌─────────────────────────────────────────────────────────────┐
│                     记忆协作架构                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   OpenClaw 记忆系统（本地）        MemOS Cloud（云端）       │
│   ┌──────────────────────┐        ┌──────────────────────┐ │
│   │   MEMORY.md          │        │   历史经验库         │ │
│   │   - 当前任务状态     │◄──────►│   - 最佳实践         │ │
│   │   - 待办事项         │   自动  │   - 错误教训         │ │
│   │   - 关键决策         │   同步  │   - 决策记录         │ │
│   └──────────────────────┘        └──────────────────────┘ │
│            │                              │                │
│            ▼                              ▼                │
│   ┌──────────────────────────────────────────────────────┐ │
│   │              Agent 工作会话                           │ │
│   │   1. 会话开始：从 MemOS 加载相关历史经验             │ │
│   │   2. 任务执行：参考 MEMORY.md 当前状态               │ │
│   │   3. 任务完成：将新经验写入 MemOS                    │ │
│   │   4. 会话结束：更新 MEMORY.md 状态                   │ │
│   └──────────────────────────────────────────────────────┘ │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**协作流程**：

1. **会话开始时**：MemOS 自动回忆相关历史经验，注入 Agent 上下文
2. **任务执行中**：Agent 读取本地 MEMORY.md 了解当前任务状态
3. **任务完成时**：关键决策和教训自动捕获到 MemOS
4. **会话结束时**：更新本地 MEMORY.md，同时同步关键信息到 MemOS

#### 9.4.3 数据流转规则

为了避免冲突和重复，我们制定了明确的数据流转规则：

| 数据类型 | 存储位置 | 同步方向 | 说明 |
|----------|----------|----------|------|
| 当前任务状态 | MEMORY.md | 本地为主 | 实时更新，不同步到 MemOS |
| 待办事项 | MEMORY.md | 本地为主 | 临时性内容，不长期存储 |
| 最佳实践 | MemOS | 云端为主 | 自动捕获，供所有 Agent 共享 |
| 错误教训 | MemOS | 云端为主 | 自动捕获，避免重复踩坑 |
| 关键决策 | 两者都有 | 双向同步 | 重要决策同时记录 |
| 代码规范 | AGENTS.md | 本地为主 | 项目级规范，版本控制 |

#### 9.4.4 冲突解决策略

**场景**：同一个知识点，本地 MEMORY.md 和云端 MemOS 记录不一致。

**解决策略**：

1. **时效性优先**：以最新修改的记录为准
2. **来源权重**：review-agent 的记录 > 开发 Agent 的记录
3. **人工仲裁**：重要冲突由项目协调者确认
4. **版本标记**：保留历史版本，可追溯变更

**实现方式**：
```yaml
conflict_resolution:
  strategy: "timestamp_priority"
  tie_breaker: "source_authority"
  authority_ranking:
    - review-agent
    - pm-agent
    - backend-agent
    - frontend-agent
    - test-agent
```

## 10 记忆技术对比分析

### 10.1 主流记忆系统概览

在 AI Agent 开发领域，记忆系统是解决上下文限制、实现长期学习的关键技术。以下是当前主流的记忆解决方案：

| 记忆系统 | 类型 | 存储方式 | 检索能力 | 共享能力 | 适用场景 |
|----------|------|----------|----------|----------|----------|
| **OpenClaw MEMORY.md** | 文件级 | 本地 Markdown | 关键词匹配 | 单 Agent | 当前任务状态、待办事项 |
| **MemOS Cloud** | 云端 | 向量数据库 | 语义搜索 | 多 Agent | 历史经验、最佳实践 |
| **LangChain Memory** | 框架级 | 内存/Redis | 窗口检索 | 单会话 | 对话历史、短期记忆 |
| **AutoGPT Memory** | 云端 | 向量数据库 | 语义搜索 | 单 Agent | 长期目标、任务历史 |
| **Claude 上下文窗口** | 模型级 | 模型内部 | 全量检索 | 单会话 | 当前对话、代码上下文 |
| **GPTs Knowledge** | 云端 | 文件存储 | RAG 检索 | 多用户 | 领域知识、文档库 |

### 10.2 详细对比分析

#### 10.2.1 存储架构对比

```
┌────────────────────────────────────────────────────────────────┐
│                     存储架构对比                               │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   OpenClaw        MemOS Cloud      LangChain      AutoGPT     │
│   ┌─────────┐     ┌─────────┐      ┌─────────┐    ┌─────────┐ │
│   │ 本地    │     │ 云端    │      │ 内存/   │    │ 云端    │ │
│   │ 文件    │     │ 向量库  │      │ Redis   │    │ 向量库  │ │
│   │ 系统    │     │         │      │         │    │         │ │
│   └─────────┘     └─────────┘      └─────────┘    └─────────┘ │
│        │               │               │              │       │
│        ▼               ▼               ▼              ▼       │
│   持久化强          可扩展性强       速度快          可扩展性   │
│   离线可用          需网络连接     会话结束丢失     需网络连接  │
│   版本可控          语义检索         简单检索       语义检索    │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

**OpenClaw MEMORY.md**：
- **优点**：零依赖、离线可用、Git 版本控制、人类可读
- **缺点**：无语义搜索、无法跨 Agent 共享、需要 Agent 主动读取
- **适用**：项目级规范、当前任务状态、待办事项

**MemOS Cloud**：
- **优点**：语义搜索、多 Agent 共享、自动捕获、云端持久化
- **缺点**：需要网络连接、有 API 调用成本、配置相对复杂
- **适用**：历史经验、最佳实践、错误教训、跨 Agent 知识共享

**LangChain Memory**：
- **优点**：框架集成度高、多种记忆类型（Buffer、Summary、Vector）
- **缺点**：会话级记忆、无法持久化、单 Agent 使用
- **适用**：对话历史、短期上下文、单轮对话增强

**AutoGPT Memory**：
- **优点**：长期记忆、语义搜索、自动写入
- **缺点**：单 Agent 使用、配置复杂、稳定性问题
- **适用**：长期目标跟踪、任务历史、个人助手

#### 10.2.2 检索能力对比

| 记忆系统 | 检索方式 | 检索精度 | 响应速度 | 支持查询类型 |
|----------|----------|----------|----------|--------------|
| OpenClaw MEMORY.md | 关键词匹配 | 中 | 快（本地文件） | 精确匹配、前缀匹配 |
| MemOS Cloud | 向量相似度 | 高 | 中等（API 调用） | 语义相似、概念相关 |
| LangChain Memory | 窗口滑动 | 低 | 快（内存操作） | 时间范围、Token 限制 |
| AutoGPT Memory | 向量相似度 | 高 | 中等（API 调用） | 语义相似、概念相关 |
| Claude 上下文 | 全量检索 | 高 | 快（模型内部） | 任意自然语言查询 |

**检索能力分析**：

1. **精确检索 vs 语义检索**
   - 精确检索（OpenClaw）：适合查找特定的待办事项、任务状态
   - 语义检索（MemOS/AutoGPT）：适合查找概念相关的经验、最佳实践

2. **检索触发方式**
   - 主动检索（OpenClaw）：Agent 需要显式调用 `memory_search`
   - 自动检索（MemOS）：通过生命周期钩子自动触发
   - 隐式检索（Claude）：模型内部自动处理

3. **检索上下文增强**
   - MemOS 支持检索结果注入系统提示词，增强 Agent 上下文
   - OpenClaw 需要手动将检索结果拼接到提示词

   - 配置：零配置，直接使用
   - 使用：Markdown 格式，人类和 AI 都易读
   - 维护：Git 版本控制，冲突易解决

2. **MemOS Cloud**
   - 配置：需要注册账号、配置 API Key、设置同步规则
   - 使用：通过插件自动捕获和回忆
   - 维护：云端管理界面，支持数据导出

3. **LangChain Memory**
   - 配置：代码级配置，选择 Memory 类型
   - 使用：框架 API 调用
   - 维护：需要代码维护，升级注意兼容性

## 11 总结

### 11.1 核心观点

1. **记忆系统是 AI Agent 协作的基础设施**
   - 没有记忆系统，Agent 只能做一次性任务
   - 有了记忆系统，Agent 才能持续学习和进化

2. **本地记忆和云端记忆不是竞争关系**
   - 本地记忆（OpenClaw）：管理当前状态，快速访问
   - 云端记忆（MemOS）：沉淀历史经验，跨 Agent 共享
   - 两者结合，优势互补

3. **多 Agent 协作必须解决记忆共享问题**
   - 独立记忆 = 重复犯错、信息孤岛
   - 共享记忆 = 经验传承、协作效率

### 11.2 实践建议

**对于刚开始使用多 Agent 协作的团队**：
1. 先用好 OpenClaw 的 MEMORY.md，养成记录习惯
2. 遇到跨 Agent 知识共享需求时，引入 MemOS Cloud
3. 制定明确的数据流转规则，避免冲突

**对于已有一定经验的团队**：
1. 建立三层记忆架构（项目级、Agent 级、云端级）
2. 配置生命周期钩子，实现自动捕获和回忆
3. 定期回顾记忆库，沉淀最佳实践

### 11.3 写在最后

记忆系统让 AI Agent 从"工具"变成了"团队一员"。它不仅能记住你教给它的知识，还能从错误中学习，在协作中成长。

正如人类团队需要知识库和文档系统，AI Agent 团队也需要记忆系统。MemOS Cloud 插件与 OpenClaw 记忆系统的协作实践，为我们提供了一个可行的解决方案。

未来，随着记忆技术的不断发展，AI Agent 的协作能力将会越来越强。而我们能做的，就是不断探索、实践、总结，让 AI 真正成为提升生产力的利器。

```yaml
# memos-config.yaml - 完整配置示例
plugin:
  name: "memos-cloud-openclaw-plugin"
  version: "0.1.11"
  
connection:
  api_key: "${MEMOS_API_KEY}"
  endpoint: "https://api.memos.openmem.net"
  timeout: 30
  
auto_recall:
  enabled: true
  trigger_keywords: ["接口", "API", "Controller", "Service", "页面", "组件"]
  max_memories: 5
  similarity_threshold: 0.75
  
memory_capture:
  enabled: true
  triggers:
    - event: task_complete
      capture: ["task_description", "solution", "key_decisions"]
    - event: error_occurred
      capture: ["error_message", "root_cause", "fix_solution"]
    - event: review_passed
      capture: ["code_quality_score", "best_practices"]

lifecycle_hooks:
  on_session_start:
    action: auto_recall
    params:
      query: "session_context"
      limit: 10
  on_task_complete:
    action: capture_memory
    params:
      type: "DECISION"
      content: "{{task_result_summary}}"

sync:
  enabled: true
  interval: 300  # 5 分钟
  conflict_resolution: "timestamp_priority"
```
